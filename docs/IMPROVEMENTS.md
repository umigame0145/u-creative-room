## テストで見つかった主な問題と修正

| 対象 | 問題 | 修正後 |
| --- | --- | --- |
| 画像結合 | 縦結合で2枚目以降が横にもずれる | x座標を0に固定し、縦方向だけ加算 |
| 画像結合 | 「調整なし」でも最初の画像サイズへ拡縮する | 各画像の元の寸法を保持し、差分は背景・透明で埋める |
| 画像結合 | 破損画像で読込が終わらない、設定変更後も古い出力が残る | 読込失敗を通知し、並べ替え・削除・設定変更で出力を無効化 |
| PDF | 元に戻す操作でFileオブジェクトを失う | 画像のFileを保持した履歴に変更 |
| PDF | 最初のページがA4固定、B5表記と実寸が違う | 最初から選択サイズを適用し、B5は182×257mmに統一 |
| PDF | 大きすぎる余白や画像の読込失敗で生成できない | 入力の検証と失敗時の操作復帰を追加 |
| コピペったん | 最初の素材行の「追加」が反応しない | 初期行にも入力・追加・削除・保存のイベントを登録 |
| CSV・保存 | カンマ、引用符、改行で列がずれる。壊れた保存データで起動しない | 共通CSV処理と保存データの検証を追加 |
| カウンター | 素早く連打すると合計が古い値で止まる | 前のアニメーションを中止し、最新の合計を表示 |
| ルーレット | 減速中にSETや設定変更ができる | 回転完了まで確定と設定をロック |
| タイマー | 終了後に再スタートできない。BGM再開で先頭に戻る | 終了時の状態をリセットし、一時停止した音声を同じ位置から再開 |
| モザイク・透過 | 適用後にプレビューが残り、透過が二重に見える | 適用・取り消し・全クリアでプレビューを解除 |
| モザイク・透過 | 数値欄の矢印キーが画像位置を変える | 入力欄では画像移動のキー処理をしない |
| 画像のJPEG保存 | 透明部分が黒くなる | JPEGは背景を塗ってから出力（画像編集は白、結合は選択背景） |

入力した文章・ファイル名をHTMLとして解釈しない処理、保存失敗の通知、CSVダウンロード用URLの解放も追加しました。

## 検証結果

- `npm run build:css`: 成功。
- `npm run check`: 23件のページ・スクリプト検査とローカル参照先の検査に合格。HTMLの見出し・canonical・重複ID、JavaScript構文などを確認しました。
- `npm test`: 19件すべて合格。CSVの往復、画像結合の座標・寸法、PDFのFile履歴・用紙サイズ、保存データ破損、カウンター連打、ルーレットのロック、タイマーの再開などを検証しています。
- ブラウザ幅390pxで全12ページ、320pxでホームとカウンター・タイマー・モザイク・透過・ルーレット、1280pxでホームと全8ツールにページ全体の横スクロールがないことを確認しました。
- 実際のブラウザで検索・分類・メニュー、画像2枚の縦結合、PDF画像の並べ替えと取り消し、カウンターの加算とCSV読込、ルーレットの停止と確定、素材の追加と保存・復元、モザイクと透過の画像読込・適用・取り消しを確認しました。確認した操作ではJavaScriptのコンソールエラーはありませんでした。

自動テストはjsdomを使用し、Canvas・音声・jsPDFの一部を代替実装にしています。実際に保存されたPNG/PDFのバイト列や、すべての描画結果を保証するものではありません。ブラウザのダウンロード操作は実施しましたが、この環境では保存されたファイルの取得まで確認できていません。

## 広告について

申告された不承認理由は「有用性の低いコンテンツ」です。Googleは独自性・有用性・ページの完成度などを審査しています。文字数の追加だけで解決するとは判断できません。[Googleの審査説明](https://support.google.com/adsense/answer/81904?hl=ja)

今回、各ツールに用途、具体的な手順、対応形式、制限、FAQを追加し、「このサイトについて」・プライバシーポリシー・問い合わせ導線を整備しました。説明は実装に合わせ、実績や利用者の声を創作していません。

既存のAdSenseコードとパブリッシャーIDは保持しました。同じIDの `ads.txt`、`robots.txt`、12ページの `sitemap.xml`、canonicalを追加しています。これらの設置だけでコンテンツ審査に合格するわけではありません。

確認したAdSense画面には「一定期間ご利用がないため、AdSense アカウントが無効になりました」と表示されていました。過去のコンテンツ不承認とは別に、現在の配信を再開するための手続きが必要です。再有効化は実行していません。[Googleの再有効化手順](https://support.google.com/adsense/answer/7237800?hl=ja)

### 公開後に必要な確認

1. `u-t-on/` の内容を、現在の公開先のルートに反映します。`common/utilities.css`、`about.html`、`ads.txt`、`robots.txt`、`sitemap.xml`を含めます。
2. `https://u-t-on.com/ads.txt` などの実際のURLと全ツールが正常に開くことを確認します。今回の環境では本番へのHTTP取得がTLSエラーになったため、本番の状態は未確認です。本番サイトに問題があると断定していません。
3. Search Consoleでクロール・インデックス・canonicalの状況を確認し、必要に応じてサイトマップを送信します。Search Consoleのアカウント状態は未確認です。
4. AdSenseでアカウントを再有効化し、表示される手順に沿って電話番号確認・サイト再審査を完了します。承認後は自動広告等の設定も確認します。[サイトの承認状態](https://support.google.com/adsense/answer/12131223?hl=ja)

審査結果と配信開始はGoogleの判断です。今回の改善によって承認を保証することはできません。
